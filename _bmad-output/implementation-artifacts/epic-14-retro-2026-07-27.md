### 3. [Informational — verified resolved] Reverse-sequencing pattern (epic-13/epic-14) already closed by today's Epic 13 retro, not a new open finding

`epic-13-retro-2026-07-27.md` documents Epic 14's first retro running while Epic 13 was still
in-progress as the 4th occurrence of pattern P6-2/P7-2/P8-3, and closed it by adding `my-epic-retro`'s
Step 1.4 ("Check for Lower-Numbered Epics Still In-Progress") — a guard that runs *before a retro
starts* and blocks/warns if any earlier epic is still open. That retro's own conclusion states "Between
the two, both directions of the P6-2/P7-2/P8-3 shape are now guarded," treating `pick-story`'s
already-existing A0 guard (done-but-unretro'd epics blocking a *new* epic's first story) and
`my-epic-retro`'s new Step 1.4 (in-progress earlier epics blocking a *retro*) as jointly sufficient —
deliberately not adding a third guard inside `pick-story` itself for continuing work on a later epic
while an earlier one is in-progress, since epics in this project are explicitly allowed to build in
parallel out of numeric order (see `epics.md`: "epic numbers are stable identifiers, not a sequencing
mandate"). Verified live: Step 1.4 is exactly what this retro itself ran through before proceeding (no
epic below 14 was in-progress at the time), confirming the guard works end-to-end, not just on paper.

**Resolution:** No new action needed. This finding is downgraded from what an earlier draft of this
audit treated as a still-open `[REPEAT]` gap — re-checking against `epic-13-retro-2026-07-27.md`'s own
Action Items table shows A13-1 already closed, not pending. Recorded here only so a future retro doesn't
re-flag the same non-gap a fifth time.

### 4. [Medium] P5-1 (`z.union` error-schema-ordering convention) remains a twice-raised, never-enforced convention

Flagged in Epic 5's original retro (2026-07-05) and reaffirmed unenforced in Epic 5's own 2026-07-26
completion-round-3 retro. No script, Makefile target, or CI rule enforces it today. Not an Epic 14
defect, but surfaced by this retro's Step 1.5 follow-through pass across all prior retro docs, and worth
naming now since Epic 14 (SSO, extensions) and later epics keep adding new error-schema unions that

**Resolution:** Tracked as debt only, not routed to a story this retro (it predates Epic 14 and isn't
owned by it) — logged here so a third recurrence is impossible to miss, and flagged to Nestor directly
in the Final Handoff summary.

### 5. [Low] Extension-status route has no org-scoping — likely intentional but undocumented as such

`apps/api/src/extensions/status-routes.ts` enforces admin-only auth (`allowedRoles: ['admin']`) but
returns one global, instance-wide manifest regardless of the caller's org, since only one
founder-configured extension loads per deployment (`loader.ts` module-level state). Not a bug today, but
no story documents this as a deliberate permanent architectural choice versus an oversight.

**Resolution:** Accepted as-is. Optional low-effort follow-up: a one-line Dev Notes addendum on `14-2`
or `14-5` documenting the choice explicitly, to pre-empt a future false-positive "missing org scoping"
finding. Not routed to a story — too small to track as anything but a documentation nit.
