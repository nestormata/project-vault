### 2. [Low] P5-1's `z.union` error-schema-ordering house rule has no enforcement mechanism

The 2026-07-05 retro's `P5-1` action item ("list the generic error schema last in any `z.union([...])`
response schema") was recorded as a team agreement but never encoded as a lint rule, a `check-*` CI
script, or even a written note in `AGENTS.md`/architecture docs. `apps/api/src/modules/org/routes.ts:214`
still lists `ApiErrorSchema` before `ActiveRotationsErrorSchema` in a `409` union. Verified this is
**not currently exploitable**: `ActiveRotationsErrorSchema`'s shape (`{error: 'active_rotations',
rotationIds}`) shares no required fields with `ApiErrorSchema` (`{code, message, details?}`), so Zod's
union validation correctly fails the first branch and falls through — this route doesn't reproduce the
`5.1`/`5.2` bug class the rule was written to prevent. But the rule itself remains unenforced project-
wide, which means a future schema pair that *does* share `ApiErrorSchema`'s required-field shape as a
subset would silently reproduce the exact bug this retro already paid to discover twice.

**Resolution:** Tracked as debt, not escalated — no live bug found. Worth a future lightweight
`check-error-schema-union-order.ts`-style script (grep for `z.union([ApiErrorSchema, ...])` patterns) if
convenient, same family as this project's other `check-*` CI guards.
