### What went well

- The epic's creation pass used a UX/architecture/QA panel, a pre-mortem, and a completeness pass
  before implementation. This prevented several incorrect assumptions from becoming code, notably
  the Story 18.6 notification-pipeline assumption, Story 18.8 role-gate assumption, Story 18.9
  public-suffix hypothesis, Story 18.11 locale-guard conflict, and Story 18.12 aggregate-scope risk.
- TDD was consistently visible in the story records. Story 18.12, for example, records red tests
  against hardcoded dashboard cards, first-project selection, and whole-request failure handling
  before the green implementation.
- Security-sensitive paths preserved existing invariants. Story 18.5 documents a batch rotation
  query scoped through RLS and cross-tenant tests; Story 18.8 retains the effective owner/org-owner
  gate and adds cross-tenant/concurrency coverage; Story 18.11 preserves Story 15.2's prohibition
  on client-controlled locale input.
- The team chose investigation over speculative fixes. Story 18.9 reproduced the reported domain
  submission as HTTP 201 and closed with actionable UX/error guidance instead of changing a valid
  validator without evidence.
- The product-surface contract was declared on all 12 story files, with `web` or `both` scope,
  evaluator-visible classification, and persona-journey stubs.

### Challenges and growth areas

- Stories 18.3 and 18.7 required explicit sequencing because both changed the dependent-systems
  region. Story 18.7 correctly established the structural baseline first.
- Story 18.11 exposed a contract boundary between pre-auth rendering, post-registration
  authentication, and the existing server-side locale guard. The implementation preserved the
  guard, but the surrounding auth shell remains only partially localized.
- Story 18.12 fixed the first-project dashboard bug and added a URL-based selector, but its source
  list is still the first paginated project page. The story's own review recorded this remaining
  limitation.
- Several stories relied on remote CI as the final gate because local `make ci` was intentionally
  stopped or blocked by environment/worktree infrastructure. In this fresh retro worktree, direct
  `pnpm` guard commands could not run because pnpm attempted to open a restricted store database;
  the status comparison was performed directly and was clean.

### 1. [Critical] [REPEAT 4x] Self-flagged UI deferral is still not tracked by a concrete artifact

Story `18-11-pre-login-and-registration-language-selection.md:119-124` records an unfixed review
finding: the surrounding login/register page shell and `MfaLoginForm` copy remain English after the
locale switch, and the review explicitly says this was deferred. The actual English copy is visible
in `apps/web/src/routes/(auth)/login/+page.svelte:24-40`,
`apps/web/src/routes/(auth)/register/+page.svelte:16-28`, and
`apps/web/src/lib/components/auth/MfaLoginForm.svelte:68-98`. No `18-11` follow-up row appears in
`_bmad-output/implementation-artifacts/deferred-work.md`, `epics.md`, or
`sprint-status.yaml`. This is the same defect class as the concrete action items P5-2, P7-1, and
P8-2: an explicit cross-story/UI deferral exists only in story prose. The existing guard is present
on disk, but `scripts/check-psc-tbd-tracking.ts:29-32` only detects a Product Surface Contract row
whose “Linked UI story” value is `TBD`; it does not detect review-finding or out-of-scope deferrals.

Because this is a recurrence of prior action-item defect class, it is Critical under the
retrospective rules and is tagged `[REPEAT 4x]`. It cannot be dismissed or recorded as debt-only
without an explicit, auditable override.

**Resolution:** Approved as both tracked work and mechanical enforcement. Follow-up story
`19-2-localize-pre-auth-shell-and-mfa-copy` is registered in Epic 19. The new
`scripts/check-story-review-deferrals.ts` check requires every unchecked review deferral to name a
live follow-up story and is wired into `make ci` and GitHub Actions. The existing 18.11 finding now
names its follow-up explicitly. No override is recorded.

### 2. [High] Dashboard project selection still excludes accessible projects beyond the first page

Story `18-12-fix-dashboard-not-showing-certificates-alerts-and-domains.md:30-38` makes the
multi-project trust requirement explicit, and its persona at lines 23-25 says a user with data in
one or more projects must see it. The shipped implementation selects from the paginated project
response in `apps/web/src/routes/(app)/dashboard/+page.server.ts:75-81`:
`projects.items.find(...) ?? projects.items[0] ?? null`. The code comment at lines 75-77 says this
is the access-controlled source, but it only contains the first page. The story's own review
finding at `18-12...md:102-105` confirms that users with later accessible projects need project-list
pagination or an all-projects loader, and states it was left unfixed. No backlog or
`deferred-work.md` entry tracks this limitation.

The current implementation preserves tenant/project authorization, so this is a completeness and
trust gap rather than evidence of cross-tenant exposure. A user with more than the first page of
accessible projects can still be told that the selected project has no relevant monitoring data
when the data exists in another accessible project.

**Resolution:** Approved as `19-1-dashboard-selector-all-accessible-projects` in Epic 19. The story
must define an all-accessible-projects selector/loader contract, preserve project-membership
filtering, and add a regression test for a matching project outside the initial page.

### 3. [Medium] Contextual-help coverage is honestly bounded but its future extension is untracked

Story `18-3-sitewide-contextual-help-text-for-forms-and-sections.md:38` explicitly narrows the raw
“most/all input fields” request to a named floor and says broader adoption can follow in a future
story. Its Dev Notes at lines 55-56 likewise say broader adoption can follow after the additive
pattern is established. The shipped implementation correctly documents this narrowing rather than
silently claiming exhaustive coverage, and the story is not a Product Surface Contract violation.
However, no backlog or `deferred-work.md` entry identifies the trigger or owner for extending the
pattern. This is contained technical/product debt, not a blocker to the delivered floor.

**Resolution:** Rule changed. `G5 — Contextual input guidance` now requires every user-facing input,
select, checkbox, and equivalent control to have visible localized explanation text connected with
`aria-describedby`. Epic 19 backlog story `19-3-contextual-help-for-all-input-fields` will audit
and fix the missing controls.

### 4. [Informational] Cross-file consistency and architecture invariants checked clean

All 12 Epic 18 story headers match their `sprint-status.yaml` entries. Epic 18 stories declare
surface scope and persona stubs. The lower-numbered-epic scan found no active story in an earlier

the expected tenant/RLS, fail-closed audit, auth/session, rate-limit, migration, and deployment

query; Story 18.8 documents cross-tenant and effective-role coverage; Story 18.11 preserves the
server-side locale guard; and Story 18.12 keeps project selection sourced from access-controlled
projects rather than introducing an org-wide aggregate.

**Resolution:** Accepted as verified. Continue using the existing checks and story-level invariant
coverage.
